# 법무사보수
- 그쪽 주소: https://부동산계산기.com/법무사보수  · 계산 위치: 서버  · 측정일: 2026-10-14 [측정:라이브 부동산계산기.com]
- 우리 대응: /법무사수수료계산기 (App.jsx CalcLegal)  · 판정: 불일치

## 1. 입력 항목
- 부동산 종류: 주택(house) / 그 외 건물(building) 토글, 요청 파라미터 realEstateType [측정: rival-capture/html/법무사보수.html:803, 표본 s13]
- 소유 구분 own=one(고정 숨김값) [측정: 법무사보수.html:804]
- 금액(과세표준) amount, 단위 만원 — 요청에 입력 숫자가 그대로 가고(예: 5000) 응답은 원 단위(50,000,000)로 되돌려준다 [측정: s02 요청·응답, 법무사보수.html:811]
- 공공비용(인지·증지) 포함 체크 publicCost=Y 와, 체크 시 나타나는 기재금액 stampAmount(만원) [측정: 법무사보수.html:798, 822, 표본 s11~s12]
- 등기 여부 record 체크(기본 체크) [측정: 법무사보수.html:837]

## 2. 계산식 정리
- 서버 계산이라 식은 응답의 비고 문구와 값으로 추정한 것이다 [추측].
- 법무사 등기 보수 = 구간별 기본액 + (구간 하한 초과분 x 요율). 예: 3억 이하 구간은 26만원 + 1억 초과액의 0.09% [측정: s05 비고 문구]
- 보수 부가세 = 보수 x 10% (s02 210,000 -> 21,000, s07 599,992 -> 59,999) [측정]
- 총계 = 보수 + 보수 부가세 + 고정 5개 항목(등기·신고 대행 5만 + 세금 신고·납부 대행 5만 + 채권매입 대행 4만 + 일당 8만 + 교통실비 8만 = 30만원) [측정: s02 총계 531,000 = 231,000 + 300,000]
- 공공비용 체크 시 수입증지 18,000원과, 기재금액 기준 수입인지를 더한다 (s11 인지 150,000 "1억원 초과 10억원 이하", s12 인지 0 "1억원 이하 주택 소유권 이전 시 면세") [측정]
- 그 외 건물(building)로 바꿔도 9억에서 보수는 880,000 으로 주택(s15)과 같았다 [측정: s13 vs s15]

## 3. 상수·구간표
- 관찰된 보수 구간(비고 문구 기준) [측정: s02~s10]:
  - 5천만 이하: 210,000원 고정
  - 1억 이하: 21만원 + 5천만 초과액의 0.10%
  - 3억 이하: 26만원 + 1억 초과액의 0.09%
  - 5억 이하: 44만원 + 3억 초과액의 0.08%
  - 10억 이하: 60만원 + 5억 초과액의 0.07%
  - 20억 이하: 95만원 + 10억 초과액의 0.05%
  - 200억 이하: 145만원 + 20억 초과액의 0.04% (31억 표본 s10 에서 관찰)
- 경계값(정확히 5천만·1억·3억·5억·10억·20억)은 모두 낮은 쪽 구간 문구로 표시됐다. 단 5천만 표본(s02)은 5천만 이하 문구, 5천만+1만원(s03)은 1억 이하 문구로 갈렸다 [측정]
- 200억 초과 구간은 표본이 없어 확정 못 함.

## 6. 판정과 불일치 예시
- 판정: 불일치 (일치 0 / 비교 10). [측정: rival-capture/runs/법무사보수/s02~s10,s15.json 과 ours-capture/runs/법무사보수/ 같은 id]
- 불일치 예시: 소유권이전 과세표준 3억(30000만원) -> 그쪽 법무사 등기 보수 440,000원 vs 우리 기본 보수 336,000원. 총합계로는 그쪽 784,000원 vs 우리 총합계는 같은 입력에서 449,600원이다 [측정: s05 양쪽 결과].
- 원인(우리 코드 읽기): 우리는 구간마다 고정액 하나만 쓰고(5천만 이하 234,000, 1억 이하 269,000, 3억 이하 336,000, 5억 이하 390,000, 10억 이하 475,000, 20억 이하 560,000, 30억 이하 645,000) 구간 안 초과분 요율을 쓰지 않는다 (src/App.jsx:3221). 그쪽은 구간 기본액에 초과분 요율을 더하는 누진식으로 보인다 [추측: 비고 문구와 값만 대조]. 그래서 같은 구간 안에서 우리 값은 고정, 그쪽은 금액에 따라 늘어난다 (s06 5억 600,000 vs s07 4억9,999만 599,992 / 우리 둘 다 390,000).
- 30억 초과: 우리는 70만원에 10억당 5만원을 더하는 식(App.jsx:3221)인데 그쪽은 31억에서 1,890,000 이다 (s10) [측정].
- 구성 차이(비교 표 밖): 그쪽 총계는 보수 + 부가세 + 대행료 3종(5만·5만·4만) + 일당 8만 + 교통실비 8만, 우리는 보수 + 교통비 5만 + 서류발급비 3만 + 부가세 (App.jsx:3225). 그쪽에 있는 공공비용(수입증지·인지)·건물 구분, 우리에 있는 증여·상속·근저당·말소 업무 유형은 서로 없다 [측정: specs/notes/법무사보수.md].

## 7. 못 찾음·미확인
- s01(과세표준 0): 그쪽이 오류 응답을 줘서 비교에서 뺐다.
- s11~s14: 우리에 공공비용·건물 구분 입력이 없어 비교에서 뺐다.
- 200억 초과 구간 요율은 표본이 없어 못 찾음.
- 그쪽 식은 서버 계산이라 코드를 볼 수 없다. 위 식은 모두 [추측]이다.
