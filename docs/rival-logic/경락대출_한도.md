# 경락대출 한도
- 그쪽 주소: https://부동산계산기.com/경락대출한도  · 계산 위치: 서버  · 측정일: 2026-10-14 [측정:라이브 부동산계산기.com]
- 우리 대응: /경락잔금대출 (id auctionloan, src/calcs/CalcAuctionLoan.jsx)  · 판정: 불일치

## 1. 입력 항목
- 금융권 선택: 1금융권(기본)·2금융권·자체 기준 3개 버튼, 숨은 칸 financeGrade [측정: rival-capture/html/경락대출한도.html:765-770].
- 감정가(최초 법사가), 낙찰가, 현재 시세: 모두 만원 단위 금액 (id appraisalAmt, bidAmt, marketPrice) [측정: 경락대출한도.html:842, 853, 866].
- 기준 4가지 체크칸과 비율 칸: 낙찰가 기준(기본 80), 감정가 기준(기본 70), 시세 기준(기본 70), 낙찰가×낙찰가/감정가 기준(체크만) [측정: 경락대출한도.html:780-828].
- 2금융권 선택 시 비율이 90/80/80으로 바뀐다 [측정: s02, s11 요청 값 bidBase=90, appraisalBase=80, marketPriceBase=80]. 자체 기준에서는 비율과 체크를 사용자가 정한다 [측정: s07~s09 요청 값].
- 우리 쪽은 낙찰가, 감정가(만원), 규제 지역 3선택(비규제 80% / 조정 70% / 투기과열 60%), 대출 금리, 대출 기간, 방 개수이다. 시세 입력과 금융권 선택은 없다 [측정: src/calcs/CalcAuctionLoan.jsx:29-34, ours-capture/runs/경락대출한도/s01.json 화면 값].

## 2. 계산식 정리
- 서버 계산이라 아래는 입출력으로 추정한 식이다 [추측]. 단 응답의 각 줄 비고가 식을 적어 준다 [측정: s01 응답].
- 낙찰가 기준 = 낙찰가 × 낙찰가 비율, 감정가 기준 = 감정가 × 감정가 비율, 시세 기준 = 현재 시세 × 시세 비율, 경락가율 기준 = 낙찰가 × (낙찰가 ÷ 감정가) [측정: s01 320,000,000 / 350,000,000 / 350,000,000 / 320,000,000].
- 예상 대출 한도액 = 체크된 기준 금액들 중 최솟값 [측정: s01~s09, s11, s12 비고 "기준 금액 중 최소값"].
- 경락가율 기준은 비율을 곱하지 않고 낙찰가에 낙찰가율만 곱한다. 낙찰가가 감정가보다 크면 이 값이 낙찰가보다 커진다 [측정: s05 낙찰 6억, 감정 5억 → 720,000,000].
- 방공제(소액임차보증금) 차감 항목은 없다 [측정: 응답 줄에 해당 항목 없음].
- 현재 시세를 0으로 넣으면 계산을 거부한다 [측정: s10 "현재 시세를 입력해 주세요!"].

## 6. 판정과 불일치 예시
- 판정: 불일치. 식 구조가 다르다.
- 우리 식: 한도 = min(낙찰가 × LTV, 감정가 × LTV × 0.9) − 방 수 × 4,300만원, LTV는 지역 선택 값 [측정: src/calcs/CalcAuctionLoan.jsx:17-23]. 그쪽 식은 금융권별 비율로 낙찰가·감정가·시세·경락가율 기준 4개 중 최솟값이다 [측정: s01].
- s03·s05: 감정가 기준 계수가 우리는 0.9 × 0.8 = 72%, 그쪽 1금융은 70%이다. 감정가가 한도를 정하는 입력에서 10,000,000원 차이가 난다 [측정: s03, s05, CalcAuctionLoan.jsx:21].
- s04: 낙찰가가 감정가보다 많이 낮을 때 그쪽은 낙찰가 × 낙찰가율 기준이 더 작아진다. 우리에는 이 기준이 없다 [측정: s04, CalcAuctionLoan.jsx:20-22].
- s11: 그쪽은 2금융 비율(낙찰가 90%)을 선택한 결과이고 우리에는 금융권 선택이 없다 [측정: s11 요청 값].
- 불일치 예시: 감정가 5억 · 낙찰가 5억 · 시세 5억(우리는 시세 입력 없음) → 그쪽 350,000,000원 vs 우리 360,000,000원.
- 불일치 예시 2: 감정가 5억 · 낙찰가 3억 → 그쪽 180,000,000원 vs 우리 240,000,000원.
