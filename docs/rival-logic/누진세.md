# 누진세
- 그쪽 주소: https://부동산계산기.com/누진세  · 계산 위치: 서버  · 측정일: 2026-10-14 [측정:라이브 부동산계산기.com]
- 우리 대응: /누진세계산기 (세목별 고정표)  · 판정: 일치

## 1. 입력 항목
- 과세표준(#taxBase, 만원)과 사용자가 직접 만드는 구간표: 구간마다 하한(min[])·상한(max[], 만원)·세율(rate[], %), 마지막 행 상한은 무한대. 행 추가 버튼으로 구간을 늘린다. "간소화 표현" 체크(simpleView)는 표시 옵션. 과세표준을 비우면 누진공제액 속산표만 보여준다. [측정: 표본 요청 s01, s10, s15, notes/누진세.md]
- 우리: 세목 버튼(종소세 / 양도세 / 증여세 / 상속세) + 과세표준(만원). 표는 고정이다. [측정: ours 표본 화면, CalcProgressive.jsx 표]

## 2. 계산식 정리
서버 계산이라 코드는 모르고, 응답에 구간별 계산 행이 찍힌다.
- 구간별 세액 = (구간 안에 들어온 과세표준) x 해당 세율, 총 세액 = 구간별 합 (s03: 1억의 10% + 1만원의 20% = 10,002,000원) [측정: s03 응답].
- 경계는 "이하" 포함: 과세표준 1억원이면 20% 구간 행이 생기지 않는다(s02 총 10,000,000원) [측정: s02].
- 응답에는 "누진세 계산표"(구간별 정액+초과분)와 "쉬운 누진공제 계산표"(세율-누진공제액)가 함께 온다 [측정: s01 응답 구조]. 우리 화면에는 이 표들이 없고 한계세율·실효세율을 보인다 [측정: ours s01].
- 우리: 구간표를 위에서부터 훑어 구간 폭 x 세율을 더한다(원 단위 정수 반올림) [측정: notes/누진세.md CalcProgressive 설명, ours s03 10,002,000].

## 3. 상수·구간표
- 증여세·상속세(세율표를 사용자가 입력한 것): 1억 10%, 5억 20%, 10억 30%, 30억 40%, 초과 50% [측정: s01~s09 요청]. 법령: 상속세 및 증여세법 제26조(상속세 세율), 제56조(증여세는 제26조 세율 적용) [측정: law.go.kr 원문, law/누진세.json].
- 종합소득세(양도소득세 기본세율과 같은 표): 1,400만 6%, 5,000만 15%, 8,800만 24%, 1.5억 35%, 3억 38%, 5억 40%, 10억 42%, 초과 45% [측정: s12~s14 요청]. 법령: 소득세법 제55조제1항, 양도소득세 기본세율은 제104조제1항이 제55조 세율을 따름 [측정: 원문 조회].
- 중요: 그쪽 표는 사용자가 입력하는 값이고 위 값은 우리 표를 그대로 넣은 것이다. 그쪽이 세율 자체를 제공하는 것은 아니다 [측정: s01 요청 필드].

## 6. 판정과 불일치 예시
- 판정: 일치 (비교 14건 모두 일치). 원 단위 정수가 전부 같다. 단, 그쪽은 세율표를 사용자가 넣는 계산기이고 같은 표를 넣어 비교한 결과라 "그쪽이 올바른 세율을 안다"는 뜻이 아니다.
- 불일치 예시는 없음. 구조 차이만 있다: 그쪽은 임의의 구간표와 누진공제 속산표를 주고, 우리는 4개 세목 고정표와 한계·실효세율을 준다.

## 7. 못 찾음·미확인
- 구간 경계에서 "초과/이하" 규칙은 그쪽이 "이하 포함"임을 s02 에서 확인했다. 구간 하한을 비워 둔 입력이나 구간이 겹치는 입력은 시험하지 않았다.
- 우리 양도세 버튼(종소세와 같은 표)은 양도세 기본세율 외 중과·단기 세율이 없다는 점을 이번 비교에서 시험하지 않았다 [측정: 표본 범위, ours 표본은 종소세·증여세만 사용].
