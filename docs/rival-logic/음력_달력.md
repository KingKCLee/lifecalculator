# 음력 달력
- 그쪽 주소: https://부동산계산기.com/음력  · 계산 위치: 브라우저(서버가 쿼리로 달력을 그림)  · 측정일: 2026-10-14 [측정:라이브 부동산계산기.com]
- 우리 대응: /음력변환계산기 (단일 날짜 변환)  · 판정: 불일치

## 1. 입력 항목
- 그쪽: 월 달력 화면. 음력 기준 / 양력 기준 탭, 이전달·다음달 링크, 윤달 옵션(lleap). 입력 칸은 없다. 음력 기준 칸에는 음력 일(1~30)과 "양력 M월 D일", 양력 기준 칸에는 양력 일과 "음 M월 D일"이 찍힌다. [측정: 표본 s01~s09 mainText]
- 우리: 변환 방향(양력->음력 / 음력->양력), 날짜 8자리, 음력일 때 윤달 여부. 결과는 음력(또는 양력) 날짜와 간지·띠. [측정: ours 표본 화면, CalcLunar.jsx]

## 2. 계산식 정리
- 그쪽: 서버가 달력 표를 만들어 주는 방식이라 변환식은 모른다 [추측: 천문 데이터 표 사용 가능성만 있고 근거는 못 찾음].
- 우리: 브라우저 Intl 'chinese' 달력에 시간대 Asia/Seoul 을 지정해 연·월·일을 받는다 [측정: CalcLunar.jsx:6]. 이 달력은 월의 시작(초하루)을 중국 표준시 기준 신월로 정하기 때문에 한국 달력과 하루 다를 수 있다고 화면에 적혀 있다 [측정: ours 화면 안내문 "중국 기준시로 계산하는 내장 달력 ... 하루 차이"].

## 3. 상수·구간표
- 상수 없음. 비교한 구간: 음력 2026년 6~12월 초하루(1일)와 2027년 1월 1일, 양력 2026-02 [측정: s01~s09].

## 6. 판정과 불일치 예시
- 판정: 불일치 (비교 9건 중 7건 일치, 2건 불일치). 두 불일치는 같은 원인이다: 우리 변환이 2026년 음력 9월 1일을 10월 10일로 두고(그쪽은 10월 11일), 그 결과 8월 30일이 있는 달을 29일짜리로 센다.
- 불일치 예시: 양력 2026-11-01 -> 그쪽 음력 9월 22일 vs 우리 음력 9월 23일. 양력 2026-10-10 -> 그쪽 8월 30일 vs 우리 9월 1일 [측정: s08, s02].
- 코드 원인(추정): CalcLunar.jsx:6 의 Intl 'chinese' 달력이 중국 기준시 월 경계를 쓴다 [측정: 코드 주석과 화면 안내문; 추측: 원인 연결]. 한국천문연구원 달력자료는 2026년 음력 9월 1일을 10월 11일, 8월을 30일(대)로 적는다 [측정: law/음력.json].

## 7. 못 찾음·미확인
- 그쪽 기본 월이 현재 양력 월 번호를 음력 월 번호로 쓰는 듯한 동작(캡처 시 "음력 2026년 10월")의 원인은 못 찾음 [추측: 주석 notes/음력.md].
- 윤달 화면(lleap=1)은 월 이동 횟수가 많아 이번 배치에서 직접 시험하지 않았다 [측정: 표본 범위].
- 월력요항 관보 원문은 못 찾음(천문법 제5조제3항이 우주항공청장의 작성·관보 게재를 정함). 한국천문연구원 달력자료 페이지는 "공식 발표 자료가 아니다"라고 밝힌다.
