- 우리 대응: /명도비용계산기 (src/calcs/CalcEviction.jsx) — 구조가 달라 부분 대응  · 판정: 못찾음

## 1. 입력 항목
- 평 수 pyeongArea(평), 층 수 floor(층) [측정: rival-capture/html/명도비용.html 입력칸, 표본 s01 요청]
- 옵션 체크: 점유이전금지 신청(injunctionYn), 열쇠비용(keyRepairYn), 사다리차(ladderTruckYn), 입회자 비용(witnessCostYn) [측정: s03~s08 요청]
- 계산 기준값 설정(customBaseValue=Y)으로 집행관 비용·1인 노무비 등을 직접 바꿀 수 있고, 기본값은 집행관 20만, 입회 5만, 2평당 1인, 1인 10만, 5평당 1대, 1톤 40만, 5톤 130만, 컨테이너 30만이다 [측정: s01 요청 파라미터, s12]

## 2. 계산식 정리
- 서버 계산이라 식은 응답 값으로 추정한 것이다 [추측].
- 집행관 수수료는 1차·2차 각각 집행관 비용(기본 20만원) [측정: s01 각 200,000, s12 각 300,000]. 평수 0 이어도 이 두 건은 나온다 (s09 총 400,000) [측정].
- 필요 인부 수 = 평수 / 2, 노무비 = 인부 수 x 1인 노무비 (20평: 10명 x 10만 = 1,000,000) [측정: s01]
- 운송 톤 수 = 평수 / 5. 5톤 이상은 5톤 차량 130만원을 쓰고 남는 톤은 1톤 40만원으로 채운다 (30평 6톤 = 1,300,000 + 400,000 = 1,700,000; 100평 20톤 = 4대 x 1,300,000 = 5,200,000) [측정: s03, s10; 계산은 문서 작성자]
- 보관 컨테이너 수: 5평·10평·20평 1개, 30평 2개, 100평 4개이고 개당 900,000원 [측정: s02, s11, s01, s03, s10]. 컨테이너 수 식과 900,000원(월 30만 x 3개월로 보임)은 [추측].
- 점유이전금지 신청은 가처분 집행관 수수료 200,000 추가(s03), 열쇠비용은 개문 비용 50,000 추가(s04), 입회자는 1차·2차에 각 100,000 추가(s07), 사다리차는 300,000 추가이며 1층(s06)과 5층(s05) 값이 같다 [측정].
- 총 강제집행 비용 = 위 항목의 합 (s01: 200,000 + 200,000 + 1,000,000 + 1,600,000 + 900,000 = 3,900,000) [측정: s01]

## 3. 상수·구간표
- 기본값: 집행관 20만원, 입회 5만원(실제 입회 비용 항목은 10만원으로 나옴), 2평당 인부 1명, 1인 노무비 10만원, 5평당 운송 1톤, 1톤 40만원, 5톤 130만원, 컨테이너 30만원 [측정: s01 요청 파라미터]
- 옵션 가산: 점유이전금지 200,000 / 열쇠 50,000 / 입회 100,000 x 2회 / 사다리차 300,000 [측정: s03~s08]
- 층수는 사다리차 비용에 영향을 주지 않았다 (1층·5층 모두 300,000) [측정: s05, s06]
- 컨테이너 수 구간(평수별)은 5·10·20·30·100평 표본뿐이라 경계 확정 못 함.

## 5. 우리 같은 입력 결과 및 대조

## 6. 판정과 불일치 예시
- 판정: 못찾음. 이유: 우리는 평수·층수에서 비용을 내는 계산식이 없고 금액을 사용자가 모두 직접 입력하는 합산기라(CalcEviction.jsx:5 주석 "고정값을 두지 않는다") 같은 입력으로 비교할 수 없다 [측정: 코드 읽기와 specs/notes/명도비용.md]. 표본 6개에서 총액을 나란히 놓으면 모두 다르다(예: 20평 3층 → 그쪽 3,900,000원 vs 우리 1,200,000원). 이는 우리에 2차 집행관 수수료·운송비·컨테이너 보관비 입력이 없거나 비워 둔 결과로, 계산 오류인지 입력 구조 차이인지 이 재료로 가를 수 없다.
- 우리에 대응이 없는 그쪽 항목: 평수 기반 자동 산정, 층수, 운송비(톤 수), 컨테이너 개수, 가처분 집행관 수수료, 개문 비용, 입회 비용, 사다리차 [측정: 그쪽 응답 항목명].
- 그쪽에 없고 우리에 있는 것: 협의 명도(이사비) 모드, 명도 지연 개월·월 보유비용 [측정: 우리 화면].
- 판정 근거 단계: R3 에 따라 대체 비교로 바꿔 일치/불일치를 만들지 않고 "못찾음"으로 둔다.

## 7. 못 찾음·미확인
- 같은 입력 구조가 아니라서 일치/불일치 표본 수는 0 으로 둔다.
- 컨테이너 개수 식과 900,000원 단가의 근거, 평수 구간 경계는 표본이 부족해 못 찾음.
- 우리 쪽 s03~s08 은 대응 입력이 없어 실행하지 않았다.
- 그쪽 식은 서버 계산이라 코드를 볼 수 없다. 위 식은 [추측]이다.
