# 중도상환수수료
- 그쪽 주소: https://부동산계산기.com/중도상환수수료  · 계산 위치: 서버  · 측정일: 2026-10-14 [측정:라이브 부동산계산기.com]
- 우리 대응: /중도상환수수료계산기 (id prepay, src/calcs/CalcPrepay.jsx)  · 판정: 불일치

## 1. 입력 항목
- 상환 금액: 단위 만원 (id amount) [측정: rival-capture/html/중도상환수수료.html:821].
- 수수료율: 단위 %, 기본값 1.4 (id rate) [측정: 중도상환수수료.html:832].
- 입력 방식 2가지. 기간입력(기본): 총 대출 기간 loanPeriod 개월, 잔존 기간 remainPeriod 개월. 날짜입력: 대출일자 loanDate, 중도상환일자 prerepayDate, 상환기일 endDate 를 8자리 숫자로 [측정: 중도상환수수료.html:810-811, 845-883, 요청 값 type=period/date].
- 우리 쪽은 중도상환 금액(만원), 수수료율(%), 대출 실행일, 상환 예정일(기본 오늘), 수수료 부과 기간(년, 기본 3)이다. 상환기일을 직접 받지 않고 실행일 + 부과 기간으로 정한다 [측정: src/calcs/CalcPrepay.jsx:22-26, 19].

## 2. 계산식 정리
- 서버 계산이라 아래는 입출력으로 추정한 식이다. 다만 응답이 식을 직접 적어 준다 [측정: s01 basis "100,000,000 × 1.40% × 18 / 36"].
- 기간입력: 수수료 = 상환금액 × 수수료율 × 잔존 개월 ÷ 총 개월 [측정: s01 700,000, s03 38,889 = 1억 × 1.4% ÷ 36의 반올림 값].
- 날짜입력: 총 대출일수 = 상환기일 − 대출일자, 잔존일수 = 상환기일 − 중도상환일자, 수수료 = 상환금액 × 수수료율 × 잔존일수 ÷ 총 대출일수 [측정: s07 549 / 1,096 → 701,277].
- 날짜입력에서 중도상환일이 상환기일보다 뒤여도 잔존일수를 날짜 차이의 절댓값처럼 계산해 수수료가 0이 아니게 나온다 [측정: s10 중도상환 20260601, 상환기일 20260101 → 잔존 151일, 수수료 192,883]. 기간입력에서 잔존이 총기간보다 커도 막지 않는다 [측정: s05 37/36 → 1,438,889].
- 끝전은 원 단위 반올림으로 보인다 [추측: s03 38,888.89 → 38,889, s12 7,012,773.72 → 7,012,774 계산 대조].
- 응답 안내문: 개월 계산은 편의상이며 실제 중도상환수수료는 일 단위로 계산된다 [측정: s01 basis].

## 3. 상수·구간표
- 세율표 없음. 수수료율은 사용자 입력, 기본값 1.4% [측정: 중도상환수수료.html:832].
- 면제 기간(3년 등)을 따로 받지 않고 상환기일 입력으로 대신한다 [측정: 입력 항목에 면제 기간 칸 없음].

## 6. 판정과 불일치 예시
- 판정: 불일치. 원인 3갈래.
- 원인 1, 끝전: 우리는 금액 × 수수료율을 먼저 곱해 내림한다. 1억 × 1.4%는 부동소수 계산에서 1,399,999.9999999998이 되어 내림하면 1,399,999가 된다 [측정: node 계산 1e8*(1.4/100) = 1399999.9999999998, src/calcs/CalcPrepay.jsx:17,19]. 그쪽은 1,400,000이다 [측정: s02, s08]. s12는 7,012,773.72를 우리는 내림(7,012,773), 그쪽은 반올림(7,012,774)한 것으로 보인다 [측정: 계산 대조].
- 원인 2, 개월 대 일수: 그쪽 기간입력은 개월 비율, 우리는 일수 비율이다 [측정: s01 18/36 = 0.5, 우리 549/1,096 = 0.5009]. s03은 1/36 = 2.78% 대 31/1,096 = 2.83%이다 [측정].
- 원인 3, 상환일이 기한 뒤인 입력: 그쪽은 날짜 차이를 절댓값으로 계산해 192,883을 내고, 우리는 남은 일수를 0으로 잘라 0을 낸다 [측정: s10, CalcPrepay.jsx:19 Math.max(0, ...)].
- 불일치 예시: 상환 1억원 · 수수료율 1.4% · 대출일 2023-01-01 · 중도상환일 2023-01-01 · 상환기일 2026-01-01 → 그쪽 1,400,000원 vs 우리 1,399,999원 (반올림 차이).
- 불일치 예시 2: 상환 1억원 · 1.4% · 대출일 2023-01-01 · 중도상환일 2026-06-01 · 상환기일 2026-01-01 → 그쪽 192,883원 vs 우리 0원.

## 7. 못 찾음·미확인
- s05(잔존 37 > 총기간 36), s06(12개월 약정), s13(수수료율 0%)은 우리 쪽을 실행하지 않아 비교에서 뺐다. 우리 쪽은 날짜 입력만 받고 개월 입력과 잔존 > 기간 같은 입력을 받지 않는다 [측정: specs/notes/중도상환수수료.md, ours-capture/runs/중도상환수수료/ 에 s05·s06·s13 없음].
- 그쪽 s01~s13 전부 status ok, success true 이며 계산 거부 표본은 없다 [측정].
- 우리 s01~s04는 개월을 날짜로 바꾼 근사 입력이라 월 기준 비교용 값이다 [측정: specs/ours/중도상환수수료.json note].
- 그쪽 끝전 처리가 반올림인지 다른 규칙인지는 표본 3건 대조뿐이라 확정하지 못했다 [추측].
